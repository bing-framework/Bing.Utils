## 实现与边界

- `PinyinCatalog` 从调用方提供的两份 UTF-8 gzip 流读取单字和词组读音；`ChineseConversionCatalog` 从两份 UTF-8 gzip 流读取简繁映射。实例完成构造后可并发读取，不关闭输入流，也不改变现有静态入口。
- `asset/pinyin/data` 和 `asset/opencc/data` 保存可独立分发的生成数据；提交到 Git 后可按路径下载。对应 README 记录来源、许可、格式和 SHA-256。分词词典继续独立存放于 `asset/segmentation`。
- 已有静态拼音与简繁入口继续嵌入相同数据，保障当前消费者无需额外部署文件。因此资源外置是新增选择，不会让静态入口自动使用外部文件。
- Text 代码没有依赖特定 .NET 6/7/8 的专用实现；单个 `netstandard2.0` 包程序集仍支持这些运行时，消除了四个程序集重复携带数据的问题。

## 分词词典叠加与搜索模式（2026-09-28）

- `ChineseSegmenter.WithDictionary` 从调用方的 UTF-8 词典流创建独立实例，业务词频覆盖基础词频；连续叠加仅复制覆盖项，基础词典由只读实例共享。输入流保持开放，词典文件仍只在 Git 资源目录分发。
