# 传输与数据流衔接实施计划

用户批准上一轮建议的首批四项：分片下载接口化、限速与任务管理、临时文件配额、数据库流适配。保留所有既有工作区改动、公开成员、默认配置、目标框架和依赖；不提交、推送、发布。

## 工作项与验收

| ID | 实施范围 | 验收 |
|---|---|---|
| T01 | HTTP 包内可选分片能力接口及 IHttpRequest 扩展 | 旧接口实现继续编译；支持与不支持实现、参数/取消、真实请求链路 |
| T02 | 可共享、动态调整的字节速率限制器和限速流 | 聚合预算、突发上限、短读退款、取消与动态调整；同步/异步读写及资源归属 |
| T03 | 分片任务选项与生命周期、检查点查询/清理 | 创建/运行/暂停收尾/恢复/失败/完成/丢弃；目标锁保护在途任务，清理保留目标且只删除所属文件 |
| T04 | 显式管理的临时文件存储、配额、统计和过期清理 | 预留容量和写入上限、并发创建、活动租约保护、过期/预览/失败报告、路径隔离 |
| T05 | 数据库读取器与逐行表格/JSON/NDJSON 双向适配 | 惰性读取、类型/空值/精度、结构、取消和提前结束资源释放，不缓存全表 |
| T06 | 中文契约、消费者、四框架和独立审查 | 定向 → 受影响项目全测 → 集成/消费者/实际 netstandard → 解决方案检查 |

限速只在显式配置后启用；共享同一个限制器即可共享预算，动态修改影响后续授权。按有界突发令牌桶控制，网络栈预读和缓冲不计作已经交付的流字节。新任务入口使用已有分片身份验证、逐片持久化和原子提交；暂停不撤回已完成片段，恢复复用旧检查点。

临时文件管理只接管其专用根目录中具有本库标记的条目，预留额度先于创建正文，不扫描删除任意外部目录。旧下载布局保留，由分片任务维护接口单独查询和清理；不把通用临时配额宣称为全磁盘配额。新接口默认不自动清理文件，由调用方明确执行清理或选择释放时删除。

数据库适配针对当前结果集；不代替数据库事务，不自动读取下一结果集。使用现有类型白名单和表格 v2 格式，普通 JSON/NDJSON 为列名对象。CSV、SSE、异步 FTP 目录操作及其他后续建议不在本批。

## 影响分析

- ChangedFiles：主包新 IO/Json 工具；HTTP 新能力接口、任务管理、分片配置及其测试/文档。
- ChangedProjects / AffectedDependents：Bing.Utils、Bing.Utils.Http 及其消费者和测试。
- ChangedPublicContracts：仅增加可选接口/独立类型及重载，不给旧 IHttpRequest 增加必需成员。
- ChangedRuntimePaths：显式限速、受控临时存储、下载生命周期、数据库逐行转换。
- ChangedProviders：本地文件系统、HTTP、ADO.NET 读取器；不引入数据库驱动。
- ChangedTFMs / ChangedBuildPackaging：无。
- ChangedBenchmarkHarness：新能力仅记录当前资源特征，before=NOT_APPLICABLE；复用未变 C02 成功路径证据。
- ChangedDocsOnly：否；RiskLevel：HIGH（并发取消、文件清理、资源所有权与公共 API）。
