# 仅审计总控提示词（Audit Only Controller）

> 版本：v1.0（连续执行版）

使用 $test-project-boundary skill，并严格遵循 AGENTS.md。

任务：执行“仅审计，不改代码”的测试归属审计与迁移规划更新。目标是基于当前 `tests/*` 实际情况，识别模块专属测试、混合测试、待人工确认项，并更新/生成规划与审计结果（如需要），但不进行任何代码迁移或拆分。

## 本轮目标模块（可选）
- 若为空：对 `Bing.Utils.Tests` 做全量审计（推荐用于新阶段启动前）
- 若指定：仅审计指定模块（示例）
  - `Bing.Utils.IdUtils`
  - `Bing.Utils.Text`
  - `Bing.Utils.Collections`
  - `Bing.Utils.DateTime`

## 执行范围
- 允许修改（文档类，仅在明确要求“落盘”时）：
  - `docs/quality/*`
- 不允许修改：
  - `tests/*`（测试代码）
  - `src/*`（生产代码）

> 默认行为：先输出审计结果与规划草案，不直接落盘；若结果完整且一致，再落盘更新文档。

## 必须遵循的规则
1. 先读取并简要总结以下规则与文档（不要跳过）：
   - `AGENTS.md`
   - `.agents/skills/test-project-boundary/refs/test-project-boundary.md`
   - `docs/quality/test-reclassification-plan.md`（如已存在）
2. 按“主要断言目标”判断测试归属，不按引用数量判断
3. 不确定项标记 TODO / 待人工确认，不要臆测
4. 本任务不修改任何测试代码文件
5. 输出结构必须可直接用于后续迁移任务

## 执行步骤（按顺序）

### 第1步：当前测试分布审计（先不改任何文件）
扫描 `tests/*`，重点分析：
- `Bing.Utils.Tests`
- 已存在的模块专属测试项目（如 `Bing.Utils.<Module>.Tests`）

输出：
- 测试项目分布概览
- 初步问题概览（模块专属测试混入、混合测试类、共享辅助类耦合等）

### 第2步：按目标测试项目分组输出归类审计结果
按“目标测试项目”分组（而不是按源项目），输出以下分类：

- 可直接迁移（文件级）
- 混合测试（需拆分）
- 待人工确认项
- 应保留在 `Bing.Utils.Tests` 的通用/跨模块项

要求：
- 给出文件路径、测试类名、分类依据（主要断言目标）
- 若指定了本轮目标模块，则仅输出这些模块相关项
- 若未指定目标模块，则优先覆盖 P0/P1 常见模块，并对其余模块给出审计待续说明

### 第3步：迁移批次规划建议（P0/P1/P2 / Batch）
基于审计结果输出迁移规划建议，包括：
- 推荐批次划分（P0 / P1 / P2）
- 每批模块清单
- 子批次建议（如 `Batch-1 / Batch-2`）
- 每批优先级与原因
- 风险点（混合测试、共享辅助类、命名空间耦合、fixture 强依赖）

要求：
- 明确哪些模块适合先做“可直接迁移”
- 明确哪些模块应先做“混合拆分专项”
- 明确哪些项需要人工确认后再迁移

### 第4步：规划文档更新草案（先展示）
如果存在 `docs/quality/test-reclassification-plan.md`：
- 输出建议更新内容（草案），包括：
  - 对应模块章节的审计结果增量
  - 批次规划更新
  - 待人工确认项增量
  - 执行记录建议（如本轮为审计轮）

如果文件不存在：
- 按模板结构输出完整草案（可供新建）

> 默认先展示草案，不直接落盘，除非你明确要求“落盘更新”。

### 第5步：（可选）落盘更新文档
仅在满足以下条件时执行：
- 审计结果结构完整
- 分类依据清晰
- 无明显冲突/重复项

可更新文档：
- `docs/quality/test-reclassification-plan.md`
- `docs/quality/migration-reports/README.md`（仅在你希望记录“审计轮”时）

## 执行策略（连续运行）
- 将本次工作视为一个端到端任务，连续执行直到完成：
  分布审计 -> 归类审计结果 -> 批次规划建议 -> 规划文档草案（-> 可选落盘）
- 不要在每个小步骤后询问“是否继续”
- 仅在以下情况暂停并请求确认：
  1) 规划文档现有内容与新审计结果出现重大冲突，无法安全合并
  2) 发现需要通过修改测试代码才能判断归属
  3) 需要工作区外写入或网络访问
- 对不确定项统一写入 TODO / 待人工确认，不中断审计流程

## 输出格式（固定）
请按以下结构输出本次任务结果：
1. 使用规则摘要（已读取哪些规则与文档）
2. 当前测试分布概览
3. 归类审计结果（按目标测试项目分组）
4. 迁移批次规划建议（P0/P1/P2 / Batch）
5. 规划文档更新草案（先展示）
6. 待人工确认项 / 风险 / 下一步建议（建议对应使用哪个总控 prompt）

## 额外稳妥要求（可选启用）
- 如果全量审计规模过大，请自动优先审计 P0/P1 常见模块，并在结尾列出未覆盖模块与建议下一轮审计范围。
- 若发现同一测试类在历史报告中已标记过状态，请在草案中标注“状态复核”而不是重复创建条目。
