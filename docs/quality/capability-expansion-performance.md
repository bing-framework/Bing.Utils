# 能力扩展性能实测（2026-10-23）

## 环境和身份

- SDK：8.0.425；运行时：.NET 8.0.31；系统：Microsoft Windows 10.0.22631。
- 输入种子 20261023；每组预热 1 次、采样 3 次；以下为中位数。每次采样前执行完整 GC，计时不含该 GC。
- 分配使用 `GC.GetTotalAllocatedBytes(true)`，覆盖进程全部线程；不使用单线程分配计数。耗时包含该场景的异步、磁盘和校验操作。
- Before 来自本轮开始时的实际脏工作区源码及产物，固定于 `artifacts/capability-expansion-2026-10-23/baseline`，不是旧 HEAD。
- Before 主包 MVID：`8b0d8107-3cbe-46d7-a102-cd4ab4f02712`；After 主包 MVID：`36c27997-0234-4384-9f02-88f885f0a0c8`。其他 DLL 和源码身份见同目录 `candidate-manifest.json`。
- 正式证据：`performance-before.json`、`performance-after-confirm.json`；程序见 `benchmarks/CapabilityExpansionProbe`。性能运行期间未并行构建或测试。

文件场景每次复制一个 8 MiB 固定随机输入；JSON 场景每次序列化同一个对象 10,000 次。分段调度分别执行 1,000/10,000 次相同的 `Task.Yield` 后抛出 I/O 异常的委托，失败不写磁盘，用于观察任务和异常调度开销。HTTP 场景用本地内存处理器返回一个 8 MiB 分片，每轮包含一次探测、一次范围请求、分片提交和最终合并，不代表真实网络吞吐。

文件写入移除了完整输入数组；JSON 默认选项及其元数据得以复用；HTTP 分片移除了整个响应缓冲和一次摘要重读。这三项的分配减少清晰可见。

**调度耗时存在回退。** 固定工作任务减少了任务保留量，正式采样的分配也低于基线，但这个异常密集场景的耗时均高于基线。HTTP 写盘的耗时同样没有改善。不能把本轮结果概括为所有路径吞吐提高；未设置或推导新的耗时百分比门禁。该微基准没有记录实际峰值并发，不能将请求并发度当作实测并发；并发不超限由回归测试单独验证。

## 诊断与停止条件

基线首次诊断因探针缺少已有的 AspectCore 运行时依赖而中断，不作为完整对照；补齐探针依赖后正式采样完成。候选首次诊断 `performance-after.json` 发现流委托适配层增加了每片异步状态和异常重抛分配；移除该层及逐片计数闭包后完成一次确认。旧诊断与原始日志保留，没有覆盖数据。

确认后不继续尝试调参跑出更优数字。本轮没有改动的压缩、正则、旧随机串、图像和反射性能路径复用原有证据；本报告不扩大这些门禁的结论范围。
