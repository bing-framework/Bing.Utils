# HTTP 维护清理并发计划

> 历史记录：本文的阶段状态和“通过”结论仅对应 2026-10-06 当时的候选。后续新增的显式递归清理能力不回写为本计划当时的默认行为；当前实现以源码和最新文档为准。

## 目标

修复文件响应缓存和断点续传侧车清理在并发写入/恢复时可能删除新数据的问题，并让清理操作兑现已公开的取消契约。保持请求默认行为、缓存格式、续传协议和公共方法签名不变。

## 五阶段计划

1. **文件缓存清理锁与重检**
   - 对每个候选 `.cache` 通过其 key 锁串行化读取和删除。
   - 锁等待传递调用方 `CancellationToken`。
   - 锁内重新读取文件并再次确认过期/损坏状态，避免删除清理扫描后新写入的内容。
   - 验收：并发写入不会被清理误删；锁等待可取消；损坏文件继续计入诊断并跳过。

2. **续传侧车清理重检**
   - 取得目标 `.binghttp.lock` 后重新扫描侧车文件和临时文件。
   - 仅删除锁内重新确认仍过期的数据；活动下载仍跳过，锁文件始终保留。
   - 验收：扫描与取得锁之间恢复的数据不会被误删；现有过期清理和取消行为保持。

3. **定向竞态与取消回归**
   - 增加文件缓存清理与写入交错、锁占用取消测试。
   - 增加续传清理扫描后更新侧车文件、活动锁和取消测试。
   - 验收：相关专项测试在 net8 通过，无死锁、部分删除或错误成功。

4. **文档与边界同步**
   - 说明清理按条目锁定、锁内重检、取消语义和保留锁文件边界。
   - 不引入后台清理、递归目录扫描、分布式锁或跨节点一致性承诺。

5. **阶段验证收口**
   - 运行相关缓存/续传专项测试和 net8 生产构建。
   - 记录现有分析器警告，不扩大到无关 Benchmark、全解决方案或外部 CI。

## 边界与限制

- 本轮不改变 `HttpRequest` 默认行为、重试策略或续传响应协议。
- `.lock` 文件不由维护清理删除，避免释放锁后发生路径竞态。
- 当时的默认 `CleanupAsync` 仅扫描指定目录顶层文件，不启动后台定时任务；后续显式递归入口是独立增量，不改变该默认行为。
- 跨进程语义依赖现有文件锁；跨节点共享和分布式一致性不在本轮范围。
